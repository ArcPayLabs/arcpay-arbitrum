description: "How ArcPay prepares swap, hedge, and yield requests for Arbitrum operators and agents without claiming execution before proof exists."

ArcPay Arbitrum treats swaps, hedges, and yield moves as governed intents first.

That means an operator or agent can prepare a route, budget, risk limit, adapter target, and evidence requirement before any wallet signature or external execution happens.

## Why Intents

Agent execution can create real treasury risk. ArcPay separates:

- planning
- policy review
- x402 or escrow setup
- wallet or smart-account signature
- execution evidence
- audit record

This avoids the common failure mode where an agent dashboard says a strategy executed before there is a transaction hash, order state, x402 verification, or signed result.

## Swap and Execution Adapters

The `/swaps` page supports Arbitrum route intents for:

- GMX execution or hedge intent
- ZeroDev smart-account execution with policy-gated sponsorship proof
- Stylus policy-module route checks
- Dune analytics/evidence links
- manual signer execution

ArcPay records the swap intent and exports a structured payload with source asset, target asset, amount, slippage, expiry, executor, policy requirement, and contract context.

## GMX Adapter

GMX is implemented as an Arbitrum Sepolia execution adapter with official contract configuration:

- status endpoint: `/api/gmx/status`
- app surface: `/swaps`
- contract docs: `https://docs.gmx.io/docs/api/contracts/addresses/`
- SDK docs: `https://docs.gmx.io/docs/sdk/v1/`

ArcPay loads the GMX `ExchangeRouter`, `Router`, `Reader`, `DataStore`, `OrderVault`, `EventEmitter`, and related testnet contracts into the swap manifest. The operator can select a route template, copy the GMX manifest, and move it through ArcPay policy review before any wallet execution.

The key rule is unchanged: no GMX route, hedge, or order can be marked complete unless the final Arbitrum transaction hash and Dune/worker evidence are attached.

## Yield and RWA Strategy

The `/yield` page supports Arbitrum strategy intents for:

- USDC conservative reserve
- WETH treasury sleeve
- GMX hedged treasury sleeve
- manual RWA review

The strategy payload includes allocation cap, drawdown cap, rebalance cadence, leverage restriction, operator approval requirement, and ArcPay module addresses.

## Evidence Rule

ArcPay should not mark a swap, hedge, rebalance, or yield action as complete unless the executor returns one of:

- Arbitrum transaction hash
- fulfilled ArcPay order id
- x402 order verification result
- Dune query or dashboard link
- signed operator record

Until then the status remains an intent.

## Production Boundary

The current implementation is ready for policy-bound agent handoff and audit capture on Arbitrum Sepolia. ZeroDev sponsorship has a live proof path through the `/execution` dashboard and published proof JSON. GMX has official testnet contract configuration and a production-gated manifest on `/swaps`. Direct signed GMX fills, Stylus execution, Dune automation, or Fhenix compute should only be enabled after each adapter is tested with reliable failure handling and clear evidence capture.
